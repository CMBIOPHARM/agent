# CMBIOPHARM 전문 에이전트 등록부

이 문서는 최상단 `AGENTS.md`를 상속하는 전문 에이전트의 번호, 역할과 운영 상태를 관리한다.
총괄 운영 규칙은 항상 최상단 `AGENTS.md`가 우선한다.

## 등록 현황

| 번호 | 역할 | 상태 | 역할 문서 |
|---|---|---|---|
| Agent 00 | 전체 운영·저장·기기·전문 에이전트 조정 | 운영 중 | `../AGENTS.md` |
| Agent 01 | 연구개발 | 설계 예정 | 추후 작성 |
| Agent 02 | 시뮬레이션 강화 | 설계 예정 | 추후 작성 |
| Agent 03 | 매일 루틴 업무 — 매일 업무일지 요약·점검 (월~금 20:30, Mac) | 운영 중 | `AGENT-03-매일업무일지.md` |
| Agent 04 | 주간 업무지시·주간 요약 (토 10시 차주 지시 초안, 일 10시 주간 요약·차주 정리 초안) | 준비 | `CMBIOPHARM/rnd`의 `agents/AGENT-04-주간업무지시.md` |
| Agent 05 | 미지정 | 비어 있음 | 추후 작성 |

에이전트 번호는 한 번 실제 업무에 사용하기 시작하면 다른 역할에 재사용하지 않는다. 역할이 종료되면 문서를 삭제하지 않고 상태를 `중지` 또는 `보관`으로 바꾼다.

## GitHub Project 운영 현황판

- CMBIOPHARM 조직의 에이전트 전용 GitHub Project 하나에서 모든 전문 에이전트의 상태와 업무를 누적 관리한다.
- 최상단 `AGENTS.md`와 각 역할 문서가 운영 규칙의 원본이며, GitHub Project는 진행 상황과 이력을 보는 현황판이다.
- 에이전트마다 상위 항목 하나를 만들고 `번호`, `역할`, `상태`, `담당 범위`, `실행 주기`, `최근 실행`, `다음 작업`을 관리한다.
- 구체적인 개발·조사·자동화 작업은 저장소 Issue로 만들고 해당 에이전트 상위 항목과 연결한다.
- 기본 상태는 `설계 예정`, `준비`, `운영 중`, `대기`, `중지`, `보관`을 사용한다.
- 완료 항목과 중지된 에이전트도 삭제하지 않고 Project에 남겨 운영 이력을 보존한다.
- Project의 상태를 바꾸면서 역할이나 저장 정책이 달라지면 관련 Markdown 문서도 같은 작업에서 갱신한다.

## Agent 00 통합 저장소 감시

- 감시 대상 저장소는 최상위 `config/repositories.tsv`에 등록한다.
- Mac의 `scripts/mac_hub_routine.sh`가 등록된 저장소를 15분마다 순회한다.
- 각 저장소에서 GitHub 연결, `main` 동기화, 미커밋 변경, 분기 상태와 미병합 원격 브랜치를 확인한다.
- 깨끗한 `main`이 `origin/main`보다 뒤에 있을 때만 fast-forward한다.
- 자동 커밋, 자동 푸시, 브랜치 병합과 파일 삭제는 하지 않는다.
- 실행 로그는 `~/Library/Logs/CMBIOPHARM/agent-hub.log`에 기록한다.

## Agent 03 매일 업무일지 요약·점검

- Mac launchd `com.cmbiopharm.daily-worklog`가 월~금 20:30 KST에 `scripts/daily_worklog/run_daily_worklog.sh`를 실행한다.
- 입력은 공유 드라이브 `CMBIOPHARM/업무일지/<이름>/` 원본(읽기 전용), 대상자는 `config/daily_worklog_people.tsv`.
- 출력은 v0 초안 `YYYY-MM-DD_일일요약_v0.docx`이며 대표 내 드라이브 `09. 인사/01. 차주업무지시/YYYY-MM-DD주/`(그 주 월요일)에 저장한다.
- 대표가 검토·수정을 지시하면 v1 이상을 공유 드라이브 `CMBIOPHARM/업무일지/`에 올린다. 자동 실행은 공유 드라이브에 쓰지 않는다.
- 실행 로그는 `~/Library/Logs/CMBIOPHARM/daily-worklog.log`에 기록한다.

## 역할 문서 필수 항목

각 역할 문서는 다음 항목을 포함한다.

1. 목적과 책임 범위
2. 실행 조건과 주기
3. 입력 자료와 신뢰할 원본
4. 생성하는 출력과 저장 위치
5. 사용할 도구와 실행 환경
6. 완료 기준과 검증 방법
7. 로그·오류 보고 방식
8. 다른 에이전트와의 인계 조건
9. 금지하거나 사람의 판단이 필요한 작업

## 실행 순서

1. 최신 `origin/main`의 최상단 `AGENTS.md`를 읽는다.
2. 이 등록부에서 배정된 번호와 운영 상태를 확인한다.
3. 해당 역할 문서를 읽고 정해진 범위 안에서 작업한다.
4. 결과를 최상단 저장 규칙에 따라 GitHub 또는 Google Drive에 저장한다.
5. 완료 결과, 저장 경로, 검증 결과와 다음 인계 대상을 보고한다.
